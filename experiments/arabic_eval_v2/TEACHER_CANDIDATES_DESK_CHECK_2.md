# Teacher candidates — desk research round 2 (2026-10-11): **no candidate RECOMMEND FOR GATE**

## Scope and method

- **Context:** both earlier teachers were rejected under the original gates: kNN-VC (`TEACHER_GATE_RESULT.md`) and OpenVoice V2 (`TEACHER_GATE_OPENVOICE_RESULT.md`, commit `55f6416`, TEACHER FAIL).
- **Desk research only:**
  - no Kaggle, no GPU, no benchmark;
  - no weights downloaded (sizes come from Hub file listings);
  - protocol v1.2, T1–T4 and the frozen data are untouched.
- **Candidates:** 5, all published speaker-anonymization or voice-conversion systems with an ASV-based privacy evaluation.
- **Sources:** official repositories (pinned commits), official model cards and licence files.
- **Two access limits** (stated, not hidden):
  - arxiv.org was unreachable from this environment, so papers were identified via search results and the repositories' own descriptions;
  - the GitHub release-asset lists of SA-toolkit failed to load, so its weight sizes were not obtained.

**Comparability warning:** published numbers come from **different protocols** than ours, and are **not** comparable with T1–T3:
- English LibriSpeech;
- an ASR trained on LibriSpeech;
- in VPC 2024, an ASV *retrained on anonymized speech* (semi-informed attacker).

They are used only as qualitative signals. A relative WER change is computed from the published pairs, inside that protocol only.

## Candidates

### C1. VPC 2024 B5 / B6 — ASR-bottleneck + vector quantization + HiFi-GAN (SA-toolkit, Champion)

**Source and licences:**

| Item | Detail |
|---|---|
| Source | `github.com/deep-privacy/SA-toolkit` @ `22c298edfa3ef92accf347053cd00826702a2c0d`. VPC wrapper `Voice-Privacy-Challenge-2024` @ `0ef5506911ca6dd142b6f713adf328051879336d` |
| Model tags | B5 `hifigan_bn_tdnnf_wav2vec2_vq_48_v1`; B6 `hifigan_bn_tdnnf_600h_vq_48_v1` |
| Code licence | SA-toolkit **Apache-2.0** (LICENSE). The VPC 2024 recipe that wraps it is **GPL-3.0** |
| Weights licence | **No statement found** on the releases page |
| Training data | LibriSpeech / LibriTTS (CC BY 4.0) |

**What it does:**
- Audio-to-audio: English ASR bottleneck features + pitch → HiFi-GAN conditioned on a **one-hot target speaker**.
- Content is carried by the bottleneck.

**Published evidence** (VPC 2024 protocol; `results/result_for_rank_asrbn_…`):
- **WER (LibriSpeech test, English ASR):** 1.844 → 4.369, i.e. +137 % relative within that protocol.
- **EER, semi-informed** (ASV retrained on anonymized speech): 33.9 % (f), 34.7 % (m).
- These are separate metrics, not comparable to T1/T3.

**Compute:**
- TorchScript models; the README says fast, and the HF Space demo exists.
- Weight sizes **not obtained**.
- CPU/Android feasibility **not measured**.

**Risks:**

| Risk | Detail |
|---|---|
| (a) Real-person target | The target is a **real training speaker**: `target_constant_spkid: "6081"` is a LibriTTS speaker, so output imitates a real person. Our rule: no real-person target without consent. CC BY does not license voice likeness |
| (b) English bottleneck | The ASR bottleneck is English-trained, so Arabic phone content is likely degraded. That is a T1 risk with no Arabic evidence |
| (c) Licensing | Weights licence unstated |
| (d) Real-time | Not streaming per se |

**Verdict: NEEDS RIGHTS REVIEW.** Rights and target blockers come first, and even after them there is no evidence for T1 in Arabic.

### C2. VPC 2024 B4 — neural audio codec language model (Panariello et al.)

**Source and licences:**

| Item | Detail |
|---|---|
| Source | VPC 2024 @ `0ef55069…` (`anonymization/modules/nac/anonymizer.py`). Coqui-TTS fork `github.com/m-pana/nac-requirements` @ `f94dd912e33fc45326e815c7677ca7825a4b1430` |
| Code licence | Fork **MPL-2.0** (LICENSE.txt, setup.py); VPC recipe GPL-3.0 |
| Weights | Bark via HF `erogol/bark` (card `license: mit`; the original `suno/bark` is MIT). HuBERT tokenizer: Bark-voice-cloning quantizer (`gitmylo/…`, repo MIT) |
| Target voices | Bark "suno_voices/v2" speaker prompts. **Provenance not verified** (synthetic or real not established) |

**What it does:**
- Audio → HuBERT semantic tokens → Bark coarse/fine LMs → EnCodec.
- Content is regenerated by a **generative LM**, so it is stochastic and can drift.

**Published evidence** (VPC 2024 protocol):
- **WER (English):** 1.846 → 5.899, i.e. +220 % relative within that protocol.
- **EER, semi-informed:** 29.4 % (f), 31.2 % (m).

**Compute (OBSERVED file sizes, `erogol/bark`):**

| File | Size |
|---|---|
| `coarse_2.pt` | 3.93 GB |
| `fine_2.pt` | 3.74 GB |
| `hubert.pt` | 1.14 GB |
| `tokenizer.pth` | 0.10 GB |

- About **8.9 GB** in total (`text_2.pt`, 5.35 GB, is presumably unused here).
- GPU-class; not plausible on CPU or Android (estimate, not measured).

**Risks:**
- Bark's language list excludes Arabic, so semantic tokenization of Arabic is unverified.
- Generative content drift is a T1 risk.
- Size.

**Verdict: REJECT.** It is the largest WER degradation among the VPC neural baselines, uses a generative content path, has no Arabic in Bark, and is impractical to deploy.

### C3. Multilingual phonetic/TTS anonymization (Meyer, Lux, Vu — Interspeech 2024; VPC 2024 B3 lineage)

**Source and licences:**

| Item | Detail |
|---|---|
| Source | `github.com/DigitalPhonetics/speaker-anonymization`, branch `multilingual` @ `9463f46e71ba75d20375bb63069c500d4fd96842` |
| TTS | IMS-Toucan `v2.5` @ `5f1dce3b…` |
| Code licence | **GPL-3.0** (repo LICENSE); IMS-Toucan Apache-2.0 |
| Weights | IMS-Toucan v2.5 release (`embedding_gan.pt`, `ToucanTTS_Meta.pt`, …); licence of the weights not separately stated |
| ASR | `openai/whisper-large-v3` |

**What it does:** a **cascade**. The ASR produces a text transcript, then a TTS speaks it with a GAN-sampled artificial speaker and modified prosody. The original audio is not converted.

**Published evidence:**
- The README states that the multilingual trials cover 9 languages (en, de, fr, it, es, pt, nl, pl, ru). **Arabic is not among them.**
- The VPC 2024 B3 single-language variant: WER (English) 1.844 → 4.352 (+136 % relative in that protocol); semi-informed EER 26.7–27.9 %.

**Compute:** Whisper-large-v3 + TTS; not CPU/Android-light (estimate).

**Risks (decisive for us):**
- Content passes through a transcript. ASR errors are **baked into the output**, and on our clips even the evaluation ASRs have original corpus WER 0.49–0.65. With a cascade, a relative increase ≤ 0.20 would need near-perfect Arabic ASR. There is no basis for that.
- GPL-3.0 code fails T4 (permissive required).
- Arabic is unevaluated.

**Verdict: REJECT.**

**What it does:** audio-to-audio. SSL content features + F0 + a pseudo speaker vector → HiFi-GAN.

**Verdict: REJECT.** Non-commercial licence fails T4, as MMS-TTS did in gate #1.

### C5. XTTS-v2 used as an anonymizer ("Your Voice Cloning System is Secretly a Voice Anonymizer")

**Source and licences:**

| Item | Detail |
|---|---|
| Model | HF `coqui/XTTS-v2` |
| Weights licence | **Coqui Public Model License 1.0.0**: "allows only non-commercial use of a machine learning model and its outputs"; "Use of the model to train other models for commercial use is not a non-commercial purpose" |
| Code | Coqui TTS, MPL-2.0 |
| Arabic | Supported: the card lists `ar` among 17 languages |

**Paper:** only a secondary summary was reachable. It says XTTS-v2 is repurposed without retraining, with "near-optimal EER across seven languages". The **primary paper was not read**, so the method and languages are unverified.

**Verdict: REJECT.** The weight licence explicitly forbids using the model, or its outputs, to train a model for commercial use. That is exactly the teacher role. This is independent of any quality evidence.

## Recommendation

**No candidate is RECOMMEND FOR GATE.** None offers a reasonable basis to expect T1, T2 and T3 together:
- No candidate has any published Arabic evidence.
- Every audio-to-audio system with published numbers degrades WER by well over 20 % relative **inside its own English protocol** (+137 % to +220 %). That is not comparable to our T1, but it gives no reason to expect ≤ 0.20 on Arabic.

**Best of the five: C1, SA-toolkit ASR-BN + VQ (VPC 2024 B5/B6) — NEEDS RIGHTS REVIEW.** Why it ranks first:
- permissive code (Apache-2.0);
- an audio-to-audio design (no transcript cascade);
- the strongest published semi-informed EER of the reviewed baselines;
- a lightweight TorchScript stack.

**Blockers before it could even be pre-registered:**
1. The weights licence must be stated by the authors.
2. Its target is a **real LibriTTS speaker**, which conflicts with our no-real-person-target rule. A synthetic target would need either a model trained with one, or a different target scheme. That is training, which is outside this task.
3. Its content bottleneck is **English-trained**. Arabic content preservation is unknown, and likely the main T1 risk.

**Engineering observation (OBSERVED + INTERPRETATION, not a criteria change):**
- Across three teachers measured or reviewed, Arabic intelligibility within T1 is the consistent failure point.
- An off-the-shelf teacher meeting T1 may require an **Arabic-trained content representation**. That implies training, which needs the separate approvals (data rights, cost) that are still open.
- The criteria stay as they are; this is only stated so that the owner can decide whether to continue the search or change the path.
